OKXBot  使用说明
================================================================

一、就一个文件
----------------------------------------------------------------
  OKXBot.exe    约 10 MB，双击即用。
  数学库、周期引擎、宏观快照全部配置内嵌，不需要任何外部文件，
  拷到 U 盘、换台电脑、放任何目录都能跑。

二、双击之后会发生什么
----------------------------------------------------------------
  1. 打印版本与周期节点摘要（风险偏好、周期进度、总敞口 E、留多少 USDT）
     v20 起：若真实敞口和引擎建议值不同，会括注一行
     「（引擎建议 xx%，已按 exposure_target 覆盖）」
     —— 一眼看出这个 E 是你定的还是引擎定的。
     紧接着打印一行【生效参数】：槽位、单仓上限、入场门槛、止损、
     熔断线，以及「与出厂默认不同」的那几项 —— 一眼看出配置生效了没有。
  2. 提示：回车=开始交易 / r=只看完整周期报告后退出 / s=调整参数
     · 直接回车 → 进入交易，按提示输 API Key / Secret / Passphrase
     · 输入 r    → 打印完整诊断报告后退出，不连交易所、不下单
     · 输入 s    → 进入参数菜单，改完会自动回到这一步（详见第九章）
  3. 之后按提示选交易模式、填参数即可。

三、命令行用法（不双击、自己开终端时用以v23举例）
----------------------------------------------------------------
  OKXBot_v23.exe                       正常启动
  OKXBot_v23.exe --help                查看全部用法
  OKXBot_v23.exe --report              只看周期报告，不交易
  OKXBot_v23.exe --selftest            内置回归自检（不联网、不下单）
  OKXBot_v23.exe --set K=V             临时覆盖参数（可写多个）
  OKXBot_v23.exe --print-config        打印配置 + 最终生效参数
  OKXBot_v23.exe --save-config [路径]   导出配置成 json
  OKXBot_v23.exe --license             查看授权状态（机器码/到期/票据）
  OKXBot_v23.exe --license-key OKX-...  写入卡密并联网激活
  OKXBot_v23.exe --license-reset       清除本机授权（换卡/排障）
  OKXBot_v23.exe --version             只输出版本号

  --selftest 会用 mock 数据跑一遍建仓主链路（补位、满仓、空池、
  槽位边界、两阶段选币、失败递补、余量补投、部分成交记账、
  止损方向、卖出/权益安全、用户参数守卫、应用内菜单、零散币归集、
  归集语义与买前归集、敞口目标、尘埃判定等共 121 项检查），
  全部 PASS 输出 ALL OK。
  换电脑、拷贝传输之后想确认 exe 没坏，跑一次即可。

  自检不会碰你的真实交易日志：mock 记录一律写进
    trading_YYYY-MM-DD_selftest.log
  （v18 起。原先会和当天的真实 trading_*.log 混在一起，复盘时分不清。）

  --set 的键：
    btc_price=70000              （默认进 SNAPSHOT，宏观快照）
    SNAPSHOT.btc_vol_ann=0.60    （显式指定段）
    TUNING.avg_corr=0.80         （引擎系数，只接受不影响总敞口的 10 个）
    USER.max_positions=6         （用户自定义，见第九章）
    USER.max_hold_days=2         （v29 起时间单位是「天」）
    REGIME_ENABLE=false          （关掉周期引擎，用内置静态参数）

  例：不改任何文件，试算 BTC 跌到 6 万时该用多少仓位
    OKXBot_v23.exe --set btc_price=60000 --report

四、怎么改参数（都不需要重新打包）
----------------------------------------------------------------
  方式 1  应用内菜单（最省事，v17 新增）：
          启动后提示行输入 s 回车，就能在菜单里直接改，不用碰任何文件。
          改一项立刻生效并回显结果，改完会自动重印【生效参数】，可反复调。
          菜单里按 w 可存盘，下次启动自动生效。详见第九章。

  方式 2  临时试算：--set K=V，只对本次运行有效
  方式 3  长期生效：
          OKXBot_v23.exe --save-config
          → 在 exe 同目录生成 regime_config.json
          → 改完之后，exe 每次启动会自动优先用它（内嵌那份作兜底）

  配置分三段：
    SNAPSHOT  宏观/行情快照（人工维护，date 过期会告警）
    TUNING    周期引擎的公式系数
    USER      策略级可调项（第九章，改完重启即可）

  改完想确认有没有生效：跑 --print-config 或 --report，末尾的
  【生效参数】会列出最终值，以及哪几项和出厂默认不同。
  写错的键、以及会改变 USDT 最大化原则的键，都会被拒绝并当场告警，
  不会静默失效。

  快照过期提醒：宏观快照日期超过 30 天，启动时会打印告警，
  提醒你更新 btc_price / days_since_ath / 波动率这几项。

  单笔上限自动托底（v13）：若「单笔上限 × 目标仓数 < 可用额度」，
  程序会自动把单笔上限抬到「额度/仓数」，避免资金用不满。
  屏幕上会打印一行「自动托底到 xx.xxU」。

五、激进型怎么选币（v12 起：先筛后买）
----------------------------------------------------------------
  每一轮刷新分两步走，不再是「边扫边买」：

  第一步 筛选（只看公式，不看下单）
    · 全市场取 USDT 现货里 24h 上涨、成交额 ≥ 50 万 U 的币
    · 按涨幅降序取前 40 个全部打分（评分 = 动量/RSI/ADX/量能/布林/
      波动率加权，再乘趋势显著性因子 0.5+0.5·P(μ>0)）
    · 按综合评分排序，取前 10 个作为「目标清单」，后面 10 个作备选

  第二步 买入（目标清单 → 备选，逐个来）
    · 先买目标清单里的 10 个；某个币校验被拒/下单没成交，
      立刻换成队列里的下一个（备选递补，屏幕会标 [备选递补]）
    · 相关性过高（ρ ≥ 0.98）的视为冗余跳过，同样往下换

  为什么这么改：旧版是「凑够 10 个候选就停止扫描」，而扫描顺序是
  按 24h 涨幅降序 —— 等于只买涨得最猛的 10 个，评分形同虚设。
  实测那批币 ATR 高达 16%、10%，还会混进 P(μ>0)=0.32 这种趋势
  根本不成立的币。改成全量打分后，目标清单的平均 P(μ>0) 从
  0.732 提升到 0.819，能自动剔掉趋势不成立的。

  注：目标清单 10 个，实际持仓数由周期引擎的分散化上限决定
      （当前节点是 5 仓），这是数学结论，不是漏买。

六、买不上怎么办（为什么没买上，去哪儿查）
----------------------------------------------------------------
  每一轮买入结束后，屏幕会打印三段：

    ── 未买入原因明细 ──
      XXX-USDT         校验 无法获取价格
      YYY-USDT         冗余 与持仓ρ=0.99
      ...（最多 8 条）
    ── 归因汇总 ──
      冗余        3 次
      预算不足    1 次
    → （可执行建议，针对性提示怎么调整）

  原因一共 5 类，含义如下：
    · 冗余      —— 与现有持仓相关性 ≥0.98，主动去相关，不是故障
    · 预算不足  —— 该币最小成交额超过剩余预算（调大单笔上限即可缓解）
    · 校验      —— 下单前的价格/状态检查没过（无法取价、价格漂移超余量）
    · 金额      —— 低于自设最小下单额 MIN_TRADE_USDT
    · 失败      —— OKX 明确拒绝，看行内 [错误码]：
                   51005/51131 余额不足   51020 精度错误
                   51121 无交易权限       50011 请求过频
                   51007/51009 数量小于最小值

  同时全过程会写进日志文件（解决「原因在屏幕上一滚就没了」）：
    exe 同目录 / trading_YYYY-MM-DD.log     按天一个文件
    · BUY-OK / BUY-FAIL / BUY-VALIDATE-FAIL  每笔下单结果
    · ROUND-SUMMARY                          每轮补位、递补、补投统计
    · IDLE                                   本轮闲置资金
    · COLLECT / COLLECT-OK / COLLECT-SKIP / COLLECT-FAIL
                                             零散币归集（v18 新增，见第六章末）
    · DEBUG                                  下单原始请求与交易所返回
  事后想复盘「某天为什么没买上」，翻这个文件即可。

  余量补投（v13）：因为评分折算和相关性折减恒 ≤1，预算天然会剩一点
  残差。轮末会用剩余预算给已有持仓加仓，最多补 4 次，直到资金投满
  或触及单仓上限。实测资金利用率从 92% 提到 100%。
  屏幕显示「余量补投 xx.xxU（预算余 xx，闲置即浪费）」。

  止损方向修复（v14）：周期引擎只下发止损宽度起点 stop_atr_init（当前 2.51
  ATR），原先终点的静态值 3.0 没被同步覆盖，导致持有越久止损越【宽】
  ——与「时间衰减」的设计意图相反。v14 起终点与起点同步，24h 内保持不变。

  止损实际百分比（容易看错）：--report 里显示「2.51 ATR = 7.53%」是按
  ATR=3% 估的；真实 1H ATR 通常远低于此（主流币 0.4~0.9%，二线币
  0.7~2.6%），所以实际止损 ≈ 2.51 × 该币 ATR%，大约落在 −1% ~ −6.5%，
  因币而异，不是统一的 7.5%。

  零散币归集没成功（v18 修复）：程序每 5 轮会把不构成仓位的零散币
  （部分成交残留、下架币、手动买入的币）卖成 USDT，门槛默认 5U。
  原先的问题是你的账户本来就小（实测约 1.7U），5U 的门槛比整个账户
  还大 3 倍，所有零散币都被【静默】跳过 —— 屏幕只有一行
  「待归集: [...]」，看不出为什么没动。v18 起：
    · 门槛变成可调项 collect_min_usdt（默认 5，范围 0~100），
      在应用内菜单的「归集」组里直接改；账户小就调成 0.5 或 1
    · 每个币的去向都会打印：卖出成功 / 跳过原因 / 失败原因，
      一个都没成功时直接补一行「→ 0 成功，原因：…」
    · 全过程写进日志（COLLECT-OK / COLLECT-SKIP / COLLECT-FAIL）
  另外修了一个死键：collect() 原来把门槛写成默认参数，Python 在函数
  定义时就求值一次，之后改 COLLECT_MIN_VALUE_USDT 根本不生效 ——
  和 v16 那个 TUNING 段死键是同一类坑，现在改成函数内读全局值。

  归集到底卖哪些币（v19 澄清）：**手里的币种全部兑换成 USDT**。
  所以归集不再区分币是哪来的 —— 账户里所有非 USDT 余额都是候选。
  唯一不卖的是【机器人当前正在持仓的币】（那是 exclude 的作用，
  避免归集替你把仓位平掉）：
    · 启动归集（选 1）→ 启动时机器人还没有持仓 → **等于彻底清空
      成纯 USDT**，然后再用这笔现金去建仓
    · 周期归集（每 5 轮）→ 排除机器人当前持仓，只清其余所有币
  另外新增**买前归集**：当现金卡住了预算（钱都在币里、USDT 不够
  下单）时，会在买入前先归集一轮，再把换来的 USDT 用于补仓。
  没有这一步，账户「权益够、现金不够」时会永远买不进去。

  卖不干净留下的「尘埃」（v23 修复）：真实账户里出现过 28~30 个市值
  0.0000U~0.1U 的碎币，日志里每一轮都是
    COLLECT-SKIP XXX 市值 0.0012U < 门槛 0.50U
  一个都卖不掉。查完因果链是这样的：
    · 每条卖出路径都【故意只卖一部分】—— 归集卖余额的 99.9%，退出 /
      清仓卖持仓的 99.8%（保险：按余额全额下单可能被交易所拒）。
      于是每卖一次就留下 0.1~0.2% 的残渣。实测对得上：
      买入 FET 花 0.32U → 退出按 0.998 卖 → 残留 0.32×0.2% ≈ 0.0006U，
      日志里正是「FET 市值 0.0005U」；TRB 买入 0.23U → 0.0005U，
      日志是「TRB 市值 0.0004U」。
    · 这些残渣不是持仓（清仓路径本来就把它们从持仓表删了），但会一直
      躺在账户里；下一轮归集想清它们，又被 0.5U 的归集门槛挡掉 ——
      门槛本意是「别为几分钱去下一次单」，对上「几十个几分钱」就变成
      了永远不动。
    · 更要紧的是：它们绝大多数【物理上卖不掉】。交易所对每个币有最小
      下单量 minSz，0.0002U 的 ZEC 远低于 minSz，挂单也成不了。所以
      这部分钱是真捡不回来了，唯一有意义的是【别再生成新的】。
  v23 做的事：把「剩余市值低于尘埃门槛」的残渣从持仓表里剔除（不再算
  持仓、不占仓位、也不再被归集的排除名单保护），并把这个门槛做成可调项
  dust_value_usdt。**卖出端那 0.998 / 0.999 的折扣本身没动** —— 也就是说
  残渣仍会生成、仍会留在账户里，只是从此不再冒充「持仓」。

七、v15：四个安全修复
----------------------------------------------------------------
  1. 部分成交不再产生「孤儿仓位」
     原来卖出只成交一部分时，程序仍按「全卖」把仓位从表里删掉，
     但账户里还剩着币 → 这半个仓位不再被监控，还会被「周期归集」
     当零散币清掉。现在改为：只成交一部分时保留剩余仓位继续监控，
     屏幕会打印「⚠ 仅成交…，剩余…继续监控」。
     另外补上了 OKX 的 closed 状态（部分成交后订单结束），原先把
     它当成失败，已卖出的部分没入账。

  2. 网络异常不再可能重复下单
     下单请求异常时会用 clOrdId 反查订单。原来查询失败也返回
     「查不到」，程序就当成「没提交」→ 可能重复下单。现在区分开：
     只有交易所明确回「订单不存在」才算没提交；查询本身失败一律
     停止动作，状态码 -2，提示你到 APP 核对 clOrdId。

  3. 权益查询失败不再用假数字
     原来余额接口一出错就把权益当成 1000U，导致预算、凯利上限、
     组合熔断全部基于假数据（熔断可能误触发或永不触发）。现在
     改成沿用上一次查到的真实权益，并在屏幕和日志里告警。

  4. 清仓不再卡在「卖不掉」
     卖出量对齐后若小于交易所最小值，原先是直接放弃 → 留下
     永远卖不掉的僵尸仓位。现在和买入端一样会抬到最小量去卖。

  这四项都由内置自检的 [J] 组守着（新增 7 项断言），改坏了会当场报错。

九、你自己能调的那些设置（v16 新增，v17 起可在应用内直接改，v18 增归集门槛，v20 增敞口）
----------------------------------------------------------------
  配置文件里多了一段 USER。绝大多数项只影响【选币 / 择时 / 退出细节】，
  动不了 USDT 最大化原则 —— 也就是「总共投多少钱（总敞口 E）」和
  「每轮尽量把钱投满」这两个底线。
  唯一的例外是 exposure_target（v20 新增）：它就是专门给你调「总共投
  多少钱」的那一个旋钮，默认 0.985（用满，见下面「敞口」组）。
  除它以外的所有键都改不动 E，写了会被拒绝。

  ── 在应用里改（v17 新增，不用碰任何文件）────────────────────
  双击启动后，在提示行输入 s 回车，就进菜单。菜单列出全部 27 项，
  每项显示当前值、取值范围、说明；和出厂默认不同的会标「出厂 xx」。

  输入方式（任选）：
    1 8              把编号 1 的项改成 8     例：max_positions 改成 8
    stop_atr=2.5     直接写「键=值」
    14               只看编号 14 的说明和改法
  另外几条命令：
    d 编号           某一项恢复默认
    d                全部恢复默认（回到引擎下发的值）
    w                存成 exe 同目录的 regime_config.json，下次启动生效
    ?                重印表格
    回车             返回
  退出菜单后会重新打印【生效参数】，可以「改一下、看一眼」反复试。

  菜单不是绕过守卫的后门：它和读配置文件共用同一套校验（同一张白名单、
  同一张黑名单、同一个槽位守卫），最后交回同一个装配函数生效 ——
  黑名单里那些「决定投多少钱」的键，在菜单里照样被拒绝。
  自检里有一条断言：菜单里除了 exposure_target，无论怎么改别的键，
  总敞口 E 都不会变 —— exposure_target 是唯一被允许动 E 的旋钮。

  它还会告诉你「你填的」和「实际生效的」差在哪，比如：
    → max_positions = 4（填的是 3，实际 4；v29 起语义是「上限」，
      默认 10、可以往【高】调（硬上限 100）。填得比「投满预算所需」
      还小会被抬上去，否则会剩钱投不出去）

  另外，先调小再调大（比如 max_positions 先设 2 再设 30）的结果，
  和「直接从默认调到 30」完全一致 —— v17 为此加了「引擎基准快照」：
  每次装配都从引擎下发值重新算一遍，不拿上一次的结果当基准，所以参数
  不会「越调越小」。同理，按 d 恢复默认回到的是【引擎下发的值】，
  而不是你配置文件里写的那个数。

  可调项（32 项，括号内是默认值）：

  敞口（把钱用满 —— v20 新增）
    exposure_target (0.985)     目标总敞口 E，占权益的比例。
                                0.985 = 把 98.5% 的权益投出去（默认，用满）
                                0.5   = 半仓；0 = 空仓（只留 USDT）
                                · 为什么上限是 98.5% 而不是 100%：
                                  现货下单要先扣手续费，账户里必须留一点
                                  USDT 才买得成，98.5% 就是「留够手续费后
                                  能投出去的最大比例」（＝下单现金比例
                                  BUY_BALANCE_RATIO，本就是同一个数）。
                                  填大于 98.5% 会被自动夹到 98.5%。
                                · 引擎本来会按宏观/周期/波动算一个「建议 E」
                                  （例如 27.2%）。v20 起这个建议只作参考、
                                  仍打印在报告里，实际敞口一律以
                                  exposure_target 为准 —— 你要求把钱用满，
                                  所以默认就按物理上限 98.5% 落地。
                                · 改完若持仓上限装不下（会剩钱投不出去），
                                  槽位守卫会自动把仓位数抬够。

  开几个仓
    max_positions (10)          同时持仓上限。默认 10，可以往【高】调
                                （硬上限 100）。引擎按相关性算出的分散化
                                建议值（加密市场通常只有 4~5）现在只作
                                【下限参考】—— 不足 10 会被抬到 10。
                                填得比「投满预算所需」还小会被抬上去，
                                否则会剩钱投不出去。
    max_position_ratio (0.25)   单仓上限，占权益比例
    pick_n (10)                 目标清单长度。只调 max_positions 而没写
                                pick_n 时，它会自动同步抬到同一水位 ——
                                否则会被 min(pick_n, max_positions) 卡住，
                                出现「改了没反应」
    target_pool (10)            筛选出的目标池大小
    backup_n (10)               备选递补队列长度
    thin_slot_guard (1)         单仓摊薄保护（v29 新增，默认开）。
                                钱少时槽位一多，单笔就被摊薄到交易所
                                最小成交额以下 → 买不进 → 钱闲置（就是
                                日志里的 IDLE 那行）。开启后会在开仓前
                                按候选池的真实最小额把槽位收窄到「每笔
                                都下得出去」。关掉 = 完全按 max_positions
                                开，宁可少买也不减仓位数。

  选什么币

    min_vol_usdt (500000)       24h 成交额下限

    trail_dd_target (0.025)     ATR 吊灯回撤目标
    peak_lock_arm_atr (1.0)     峰值锁定启用阈值（v28 新增）：峰值浮盈
                                达到几个 ATR 才启动棘轮。0 = 立即启用
    peak_lock_keep (0.65)       峰值锁定保留比例（v28 新增）：启动后

    portfolio_max_dd (0.12)     峰值回撤熔断线 → 全部平仓 + 冷却

  归集（把币全部换成 USDT）

                                5U 是「绝对金额」，几 U 的小账户碰上它

    dust_value_usdt (0.1)       尘埃门槛（v23 新增）：一个持仓的【剩余市值】
                                低于此值就不再算【持仓】。
                                · 成因：所有卖出路径都只卖 99.8%~99.9%
                                  （躲开「按余额全额下单被交易所拒」的保险），
                                  残留 0.1~0.2% —— 40U 的仓位正好留 0.08U。
                                · 为什么必须剔出持仓：残留留在持仓表里，会被
                                  周期归集的排除名单（机器人持仓）保护起来
                                  → 永远轮不到归集清它，还白占仓位数、白吃
                                  风险预算。
                                · 只改「还算不算持仓」，卖出逻辑本身不动。
                                  取不到价时绝不当尘埃，不会误扔真实仓位。

  三条守卫（你绕不过去，也不需要绕）

      —— 免得改了却没生效还不知道
    · 黑名单：KELLY_FRACTION / per_max / BUY_BALANCE_RATIO 这些「决定
      投多少钱」的键会被拒绝并告警。CAPITAL_UTILIZATION 本体也不接受
      直接写 —— 要动总敞口只能用 exposure_target 这一个口子（v20 起；
      它内部就是写 CAPITAL_UTILIZATION，但会夹在 98.5% 上限内）。
    · 槽位守卫：持仓上限如果小到装不下总敞口 E（会剩钱投不出去），
      自动抬到「能投满预算」的最小仓位数，并打印一行说明
    · 摊薄保护（v29）：反过来，槽位如果多到单笔金额低于交易所最小
      成交额，开仓前会把槽位收窄到「每笔都下得出去」，并打印 + 记一行
      SLOTS-THIN 日志。两道守卫一抬一收，目标是同一个：钱不闲置。
      开关就是上面的 thin_slot_guard。

十、卡密授权与加密壳（v21 起）
----------------------------------------------------------------
  这个版本加了使用授权，一卡一机（绑定本台电脑）。

  首次运行    提示你输入卡密，联网激活一次。激活成功后本机保存一张
              3 天有效的【离线票据】—— 期间断网也能启动（交易所 API
              本来就要联网，授权不该成为断网的第二个故障点）。
  票据过期    自动联网续期一次；续期失败会给出明确提示，不会一上来锁死。
  换电脑 /    重装系统会改变机器码，需要联系客服解绑后重新激活。
  重装系统    把本机的票据文件拷到别的电脑无效（票据里绑了机器码）。

  命令行：
    OKXBot_v23.exe --license              查看机器码 / 卡密方案 / 到期日 / 票据状态
    OKXBot_v23.exe --license-key OKX-...  写入卡密并立即联网激活（客服远程协助用）
    OKXBot_v23.exe --license-reset        清除本机授权信息（换卡/排障用）
    OKXBot_v23.exe --version              只输出版本号

  票据用 RSA-SHA256 签名，客户端只内嵌【公钥】—— 公钥泄露无害（伪造不出
  票据），私钥只在授权服务器上。之所以不用 HMAC：HMAC 的密钥必须内嵌进
  exe，一旦被逆向出来，谁都能自签「永久授权」。另有防回拨：系统时间被
  调回 24 小时以上会被视为篡改，强制联网校验一次。

  加密壳（v21 起）：源码不再以明文进 exe —— 打包时先编译成字节码，再用
  lzma + HMAC 流加密装进启动壳里，反编译看不到业务源码；中间产物
  build_prot/ 里也只有密文。
  （v22 修了一个打包缺陷：启动壳没把入口模块登记进 sys.modules，导致 exe
   里读到的全局表跟业务无关 —— 源码自检全过、exe 装配用户参数时才报错。）

  注意：--report 现在需要授权，所以发版流水线的版本复核改用 --version。

十一、注意
----------------------------------------------------------------
  · 首次启动比源码慢 1-2 秒（单文件自解压，正常）。
  · 杀毒软件可能误报 PyInstaller 打包的 exe，加白名单即可。
  · exe 和源码版不要同时跑，同账号多实例会互相打架。
  · 只在 OKX 模拟盘充分验证过再上真仓。
  · 把参数调激进（放宽止损 / 拉长持有 / 放低选币门槛）会直接放大
    回撤，这些键都不在「不影响收益」的范畴里 —— USDT 最大化原则只
    保证「钱不闲置」，不保证「一定赚钱」。
